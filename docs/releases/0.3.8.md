# v0.3.8 — the same output, sooner: matching, SfM and PrepareDenseScene, and CUDA SIFT that repeats

Every speed-up in this release gives the output it gave before, to the bit. The one change of output
is a bug fix that makes NVIDIA runs repeat. At Meshroom 2025.1's RANSAC defaults, FeatureMatching's
geometric filtering on 41 views takes 16.4 s instead of 36.8 s. StructureFromMotion reads features
and colours faster: 307.8 s to 240.9 s on the 884-photo False Door. On a host with four hardware
threads, PrepareDenseScene compresses its EXR files with libdeflate and undistorts on the GPU, and on
an i3 the stage is 38 % faster. A race in PopSIFT's CUDA descriptor kernel is fixed, so feature
extraction on NVIDIA cards now repeats exactly, as it already did on AMD.

## What changed

The measurements are in docs/04 (the 0.3.8 sections) and docs/15 (AC-RANSAC).

**Fixes:**
- **CUDA feature extraction repeats.** PopSIFT's descriptor normalisation let the last block's spare
  warps normalise the last descriptor of an image a second time, racing the warp that owns it. At most
  one descriptor per image could come out wrong, and only on NVIDIA: in the 0.3.7 gate, one of about
  970,000 on Windows and four on Linux. Both CUDA packages carry the fix (step 3e of
  `apply_popsift_patch.py`). The AMD packages never showed the race, and their bytes are unchanged.
- **The UNTESTED lists are back.** The Windows zip lists the GPU targets no card here has run in
  `gpu/<family>/UNTESTED` again, and the Meshroom launcher now announces a listed target, as
  `cheshire-run.cmd` always did. v0.3.2 to v0.3.7 shipped no list.
- **`CHESHIRE_BACKEND=auto` follows the package.** It runs a CUDA package when an NVIDIA card answers
  `nvidia-smi`, and an AMD package when none does. Until now a paired CUDA package ran nothing unless
  `CHESHIRE_BACKEND=cheshire` was set.

**SfM around Grin, continued** (8a-8c, all exact):
- **8a, the features' read.** A `.feat` file is read in one go and parsed with `std::from_chars`
  instead of a stream iterator, with the same bits. Every node that reads features gains: on the
  False Door the read went from 44.1 s to 0.84 s. `CHESHIRE_FEAT_READ=0` restores upstream's read.
- **8b, the colours' read.** An 8-bit photo is read as 8 bits where upstream round-trips it through
  float, with the same bytes; the colours went from 38.0 s to 14.4 s on the False Door.
- **8c, the tracks.** TracksBuilder no longer fills a set of tens of millions of nodes, and the
  tracks' pyramid runs on every core: 0.85 s to 0.35 s on the engine bay.

| False Door, RX 9070 box, back to back | 0.3.7 | 8a + 8b |
|---|---|---|
| StructureFromMotion | 307.8 s | 240.9 s |
| features | 44.1 s | 0.84 s |
| colours | 38.0 s | 14.4 s |
| output | | the same digests |

**AC-RANSAC** (8d and 8e, exact; docs/15):
- **8d, skip the models that cannot win.** AC-RANSAC uses a model only when its NFA beats the best so
  far, and about 0.04 % of the models do, yet every model paid for a sort of its residuals and a
  scan. A histogram of the unsorted residuals bounds the NFA a model could reach; a model whose bound
  cannot win skips the sort and the scan (99.66 % of them on 41 views at 50,000 iterations).
  `CHESHIRE_ACR_BOUND=0` sorts every model; `CHESHIRE_ACR_BOUND_CHECK=1` also sorts and scans every
  skipped model, and none was ever below the threshold.
- **8e, the epipolar residuals in one vectorised loop.** It repeats Eigen's arithmetic operation for
  operation: 7.86 billion residuals compared, all identical. A self-test on first use falls back to
  the per-point loop if a build's Eigen or flags ever differ. `CHESHIRE_ACR_RESIDUALS=0` turns it off,
  `CHESHIRE_ACR_RESIDUALS_CHECK=1` computes both and counts.

| geometric filtering, RX 9070 box | 0.3.7 | 8d | 8d + 8e |
|---|---|---|---|
| 41 views, 50,000 iterations (Meshroom 2025.1) | 36.8 s | 18.8 s | 16.35 s |
| engine bay, 2048 iterations (Meshroom 2023.3) | 20.2 s | 14.6 s | |

The paired nodes keep Meshroom's RANSAC defaults: changing one would make a paired 2025.1 run differ
from a stock one for a reason that is not Cheshire's code. The QR nullspace stays opt-in
(`CHESHIRE_QR_NULLSPACE=1`, faster but not bit-identical), and AC-RANSAC does not move to the GPU.

**PrepareDenseScene on four-thread hosts** (8f and 8g). Measured on house-pc's i3-4330 (two cores,
four threads) with a 524-photo job: the stage took 930 s, all of it CPU, and 47 % of that compressing
EXR files.
- **8f, libdeflate for the EXR chunks.** The Linux packages' OpenEXR 3.1 compresses with zlib, at
  73 MB/s on that CPU; libdeflate does 180 MB/s. PrepareDenseScene now builds the ZIP chunks with
  libdeflate, the same pixels in a file OpenEXR reads as before. On by default where OpenEXR is older
  than 3.2 (the Linux packages); Windows' OpenEXR 3.4 already compresses with libdeflate, and forced
  on there the files are byte for byte OpenEXR's. `CHESHIRE_EXR_DEFLATE_WRITE=0|1` overrides,
  `CHESHIRE_EXR_DEFLATE_WRITE_CHECK=1` reads every file back.
- **8g, the undistortion on the GPU.** CheshireRemap repeats AliceVision's bilinear sampler operation
  for operation, in double precision and without fused operations, so every image comes out as the
  CPU loop's. On by default with four hardware threads or fewer: on a twelve-thread CPU the copies to
  and from the card cost more than the loop. `CHESHIRE_UNDISTORT_DEVICE=0|1` overrides,
  `CHESHIRE_UNDISTORT_DEVICE_REMAPPERS` bounds the images in flight, `CHESHIRE_UNDISTORT_DEVICE_CHECK=1`
  runs both and compares.

| PrepareDenseScene, house-pc (i3-4330, GTX 1080 Ti), 40 of the 524 views | wall |
|---|---|
| 0.3.7 | 71.2 s |
| 8f | 51.2 s |
| 8f + 8g | 43.8 s |

On the whole 524-photo job that is about 930 s down to about 570 s.

## Validation

Each package is gated as the file you download, on its own card. The gate is 0.3.7's: the
15-configuration mini6 matrix and 41 views (`base`, `verify`) through Meshroom 2025.1, and a shorter
mini6 check (`base`, `defaults`, `cpufallback`, `verify`) through 2023.3, every run scored at eight
nodes. New in 0.3.8:
- FeatureMatching has to announce the AC-RANSAC bound (8d) in every run;
- `verify` also checks the colours' read (8b) in SfM, the bound and the epipolar loop (8d, 8e) in
  FeatureMatching, and the libdeflate writer and the GPU undistortion (8f, 8g) in PrepareDenseScene,
  both switched on whatever the platform's default, so every package checks them on its own card;
- `cpufallback` turns the GPU undistortion off with the other GPU paths.

| package | hardware | 2025.1: mini6 | 2025.1: 41 views | 2023.3: mini6 |
|---|---|---|---|---|
| Windows AMD | RX 9070 (rocm7.2 gfx12-generic payload) | 15/15 at 8/8 | base 383 s and verify 806 s at 8/8 | 4/4 at 8/8 |
| Windows AMD | RX 5500 XT (hip6.2 gfx1012 payload, bench-pc) | 15/15 at 8/8 | base 1056 s and verify 2316 s at 8/8 | 4/4 at 8/8 |
| Linux AMD | RX 6750 XT (house-pc) | 15/15 at 8/8 | base 616 s and verify 1707 s at 8/8 | 4/4 at 8/8 |
| Windows CUDA | GTX 1080 Ti (bench-pc) | 15/15 at 8/8 | base 909 s and verify 2211 s at 8/8 | 4/4 at 8/8 |
| Linux CUDA | GTX 1080 Ti (house-pc) | 15/15 at 8/8 | base 671 s and verify 1727 s at 8/8 | 4/4 at 8/8 |

`base` on 41 views is faster than 0.3.7's on every card (433, 1398, 881, 1277 and 931 s), most on house-pc's
four-thread i3. `verify` takes about as long as before, since it now also sorts and scans every model the
bound skipped and computes every residual both ways.

Every new self-check came out identical on every card. On 41 views each card skipped about 32 million
models with none below the threshold, and computed about 9.7 billion epipolar residuals identical to
upstream's. The epipolar loop held on every arithmetic path the packages have: AVX2 with fused
multiply-adds, AVX without, GCC on Linux, and MSVC. The GPU undistortion gave the CPU loop's pixels on
RDNA1, RDNA2, RDNA4 and Pascal, under HIP and CUDA on both systems.

**CUDA feature extraction repeats now.** On the GTX 1080 Ti, the 41-view `base` and `verify` runs gave the
same features (all 82 files) and the same reconstruction on both systems. 0.3.7's pairs differed in four
descriptors on Linux and one on Windows. On every card the two runs gave the same depth maps.
