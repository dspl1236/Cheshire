# v0.4.2 — DepthMap's GPU stages without double precision: the same depth maps, the False Door's DepthMap 31 % shorter

DepthMap's GPU work spent much of its time on a handful of double-precision instructions that AMD cards run at a
fraction of their single-precision rate, and on a division compiled to eleven instructions. Three exact steps replace
them. On the 884-photo False Door (Photogrammetry Experimental Fast Ransac, Meshroom 2025.1, an RX 9070), the
DepthMap node's chunks take 1,297 s against 0.4.1's 1,878 s (run alternately, chunk by chunk), and all 1,652 of
its depth and similarity maps are the same bytes as 0.4.1's. The replaced functions were checked beyond the test sets:
11b's and 11c's on all 2^32 inputs, 11a's three-argument one on 17.2 G.

## What changed

The measurements and the proofs are in docs/04 (the sections "After 0.4.1").

**11a, the colour distances without double precision.** Every patch sample weighs its colour difference from the
patch's centre in both cameras. HIP's `norm3df` (OCML's `len3`) converts the largest component to a double just to
read its exponent. Cheshire reads the same exponent from the float's bits and otherwise runs the library's own steps,
so the result is identical. Checked on 17.2 G inputs of four kinds; a False Door DepthMap chunk 88 s to 67 s.

**11b, the patch samples' projections with an exact reciprocal.** HIP compiles the projections' `1/z` as a correctly
rounded division, eleven instructions, twice per sample. Cheshire corrects the hardware reciprocal with two FMAs
(Markstein's method), which gives the correctly rounded result for any reciprocal accurate to one ulp; the one
significand where it would not, and out-of-range values, take the division. Proved for every significand and checked
on all 2^32 inputs on the card; 2.5 % more.

**11c, the colour optimisation's angles without double precision.** Upstream computes these angles with a
double-precision `acos`, about 65 FP64 instructions, twice per pixel and iteration. Cheshire computes them in
float-float arithmetic from IEEE operations only, so the same on every card, and uses the result only where every
value near it rounds to the same float; elsewhere (about 4 inputs in a million) upstream's double path runs. Checked
on all 2^32 inputs; the colour optimisation 13.7 s to 5.0 s of a chunk, the chunk 12 % shorter.

Each step has a switch that restores upstream's code: `CHESHIRE_DEPTHMAP_LEN3=0`, `CHESHIRE_DEPTHMAP_RCP=0`,
`CHESHIRE_DEPTHMAP_ACOS=0`. The steps are HIP only: the CUDA packages keep NVIDIA's functions, and say so in the log.

**Scoped and dropped:** compiling DepthMap's kernels for 64-wide waves gave nothing on the RX 9070 (docs/roadmap.md).

## Validation

Each package was checked as the file you download, on its own card where one was available (docs/04, "The 0.4.2
release round").

| package | hardware | 2025.1: mini6 | 2025.1: 41 views | 2023.3: mini6 |
|---|---|---|---|---|
| Windows AMD | RX 9070 (rocm7.2 gfx12-generic payload) | 19/19 | base 313 s, verify 721 s, experimental 288 s, fastransacexp 258 s, verifyexp 748 s | 4/4 |
| Linux AMD | RX 6750 XT (house-pc) | 7/7 | experimental 566 s (and 586 s with 11a-11c off: the same depth maps) | 1/1 |
| Linux CUDA | GTX 1080 Ti (house-pc) | 7/7 | experimental 631 s | 1/1 |
| Windows CUDA | not run on an NVIDIA card in this release (below) | | | |

Every run passed. On the RX 9070 every configuration's depth maps are 0.4.1's gate's byte for byte, except
`cpufallback`, whose digest has changed with every release since 0.3.6; the 41-view runs take 5.7-8.5 % less than in
0.4.1's gate. On the RX 6750 XT and the GTX 1080 Ti every depth map is the previous gate's on that card byte for byte, and on
the RX 6750 XT the 41 views with 11a-11c switched off give the same depth maps.

**The Windows CUDA zip was not run on an NVIDIA card in this release**, nor in 0.4.0 and 0.4.1: its test box is still
down. Its eight new-pipeline programs ran this gate's 41-view Photogrammetry Experimental command lines on the RX 9070
box from the zip alone; all finished, and SfMExpanding placed all 41 cameras within 0.0028 % of the scene's radius of
the AMD zip's reconstruction. If you run it on a card, a note on how it went is welcome. The Windows AMD zip's hip6.2
payloads (RDNA1, and RDNA2 under Windows) were not run on a card either; their code is the gated payloads' code,
compiled for their targets by the same chain.
