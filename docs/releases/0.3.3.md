# v0.3.3 — the eighth node, the first large sets, and clean binaries

An upstream crash found and fixed on an 884-photograph set, two CPU nodes cut down, the texture
downscale on the GPU, SuiteSparse out of the Windows packages, and the gates run at 7 of 7 ports on
every card.

## What changed

**StructureFromMotion is paired.** Meshroom's own `aliceVision_incrementalSfM` died three of
three times on the 884-view False Door of Ptahshepses (British Museum) at view 830-834 with
`[fatal] invalid map<K, T> key` - the crash of Meshroom issue #2344. The mechanism: when the
candidate search runs dry mid-pass, the resection loop exits with the views resected since the
last bundle adjustment still pending; they are never adjusted, never handed to the local-BA graph,
and a later edge to one of them throws. The paired binary finishes the pass with the bundle
adjustment it owed (`CHESHIRE_SFM_PENDING_BA=0` restores upstream), and the graph skips an edge it
cannot hold instead of throwing. Verified on the same features and matches (833 poses, 1,355,362
landmarks, the fix fired twice) and through Meshroom end to end. Everything the fix runs is
existing code in a different order; it is on the upstream issue with the diff.

**The texture downscale on the GPU.** OpenImageIO's lanczos3 resize, transcribed: tap weights
computed on the host exactly as OIIO computes them, the accumulation on the device in OIIO's
order. `CHESHIRE_GPU_RESIZE_CHECK=1`: 0 of 50,331,648 channels differ, on every card, on each of
52 atlases of the 884-view set. Texturing on the engine bay: 176 s to 124 s.

**PrepareDenseScene's undistortion map is computed once per intrinsic** instead of per pixel per
image (`CHESHIRE_UNDISTORT_MAP=0` restores). Exact; the node is I/O-bound on every box we have,
so the wall-clock gain is small (133 s to 127 s on the engine bay).

**SuiteSparse is out of the Windows packages.** Versions 0.3.0 to 0.3.2 shipped `libspqr.dll` and
`libcholmod.dll` (GPL) through vcpkg's Ceres, as Meshroom's own Windows release does. Ceres 2.2.0
is now built without SuiteSparse (Eigen's sparse backend with METIS ordering); on the 884-view
set the linear solver takes 304 s against 323 s, no penalty at this size. Both packagers refuse
a package that carries the GPL libraries. The Linux bundle's Ceres never had them.

**No FMA contraction in the ports on CUDA either.** nvcc ignores the clang pragma the ports use, so
the CUDA builds contracted a*b+c where the CPU reference rounds twice; the first float-exact
self-check to run on a CUDA card (the resize check on a GTX 1080 Ti: 7,772,469 of 50,331,648
channels) found it. Port sources compile with `--fmad=false` on the CUDA backend; upstream's
depth-map kernels are unchanged, since byte-identity with the CUDA reference depends on it.

**Profiles for the CPU nodes** (`CHESHIRE_PDS_PROFILE=1`, `CHESHIRE_BA_PROFILE=1`) and a sliced
GPU matcher variant (`CHESHIRE_MATCHER_SLICED=1`, byte-identical, slower on RDNA4, opt-in).

## The large sets

| set | box | result |
|---|---|---|
| False Door, 884 photos at 6000x3376 | Ryzen 5 5600X + RX 9070 (Windows) | 6.4 h of compute, 8,136,271 faces, 52 atlases; every self-check zero |
| Mill 19 Rubble, 1678 drone photos at 4608x3456 | i3-4330 (2 cores, 2013) + RX 6750 XT (Linux) | 16.0 h, 3,350,047 faces, 34 atlases; 164 GB of cache |

On the Rubble box, feature extraction for 1678 views took 12.6 minutes on the card; the CPU's
share of the 16 hours is SfM and half of matching. Details, per node, in docs/04.

## Validation

Every package gated as the file you download, through the 12-configuration mini6 matrix with
Meshroom 2023.3, scored at seven ports plus the paired SfM node.

| package | hardware | result |
|---|---|---|
| Windows AMD | RX 9070 (rocm7.2 gfx12-generic payload) | 12/12 at 7/7 |
| Windows AMD | RX 5500 XT (hip6.2 gfx1012 payload) | 12/12 at 7/7, 0 bugchecks |
| Linux AMD | RX 6750 XT | 12/12 at 7/7 |
| Linux CUDA | GTX 1080 Ti | 12/12 at 7/7; 41-view depth maps 82 of 82 files byte-identical to upstream's CUDA 11.3 build |
| Windows CUDA | GTX 1080 Ti | 12/12 at 7/7, 0 bugchecks, no GPL library |

Every self-check the `verify` and `texcheck` runs assert passed on every card: max-flow labelling,
GPU knn (by vertex), segments, tedge cell counts, facet weights, filterByPixSize, texture padding
(0 of 67,108,864 texels) and the new resize (0 of 50,331,648 channels). The RDNA2 Windows
payloads (gfx1030-1036) are built from the same source as the gfx1012 one and were not run on
hardware this round.

## Also

* The harness takes `CHESHIRE_E2E_OVERRIDES` for one-off Meshroom overrides, and its `RESUME`
  clears interrupted chunks; two disk incidents on the 1678-view run are written up in docs/04,
  including the one it cannot catch yet (a cached input that no longer decodes).
* Known: a GPL-free Windows package means the Windows bundle adjustment uses Eigen's sparse
  solver; at thousands of poses CHOLMOD would pull ahead, and that is the point to revisit.
