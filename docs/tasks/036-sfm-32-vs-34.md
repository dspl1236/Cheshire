# Task: which AliceVision SfM change between 3.2.0 and our 3.4 base moves the reconstruction? (read-only)

## Background (measured; details in docs/04, the "0.3.6" sections)

- Cheshire builds on AliceVision `develop` at 2cb1a39 (2026-08-28, version.hpp 3.4.0). Meshroom
  2023.3, which the packages pair into and which the mesh gate compares against, ships AliceVision
  3.2.x. Confirm the exact tag or commit from Meshroom 2023.3's release.
- On the 107-photo engine bay, Cheshire's meshes sit about 0.05 % of the diagonal from upstream
  Meshroom 2023.3's. That is beyond upstream's own run-to-run spread: medians 0.0022-0.0025
  against 0.0017-0.0018. After aligning on the cameras, Cheshire's SfM frame still sits about
  1 degree from upstream's; two upstream runs sit 0.06 degrees apart.
- Setting Cheshire's non-bit-identical SfM switches to upstream's changes nothing: analytic
  Jacobians off, persistent Problem off, per-task generators off.
- Stage swap: upstream's own SfM, then Cheshire's dense stages. That lands as close to upstream as
  upstream's two runs are to each other (medians 0.0015). So the difference is in SfM, and it comes
  from the AliceVision version, not from Cheshire's patches.

## What to find

Read the diff between AliceVision 3.2.x (Meshroom 2023.3's) and 2cb1a39 in the incremental SfM path.
List the changes that can move its output: the frame orientation (about 1 degree), the geometry
(0.05 % of the scene), or the landmark set.

- `src/software/pipeline/main_incrementalSfM.cpp`: option defaults, and what runs after
  reconstruction. `useAutoTransform` is the first suspect: it re-orients the scene at the end of
  SfM, and a change in how it picks the frame would give exactly a fixed rotation.
- `src/aliceVision/sfm/pipeline/sequential/ReconstructionEngine_sequentialSfM.cpp`: initial pair
  choice, next-best-view selection, resection, triangulation, outlier thresholds.
- `src/aliceVision/sfm/bundle/BundleAdjustmentCeres.cpp` and the cost functions: loss function,
  thresholds, which blocks are refined, Ceres options.
- `src/aliceVision/sfm/utils/` and `sfmDataUtils`: alignment and transform helpers
  (`computeNewCoordinateSystemFromCameras` or similar), scale normalisation.
- Track building, relative pose, `robust_estimation`: estimator defaults and thresholds.
- `CMakeLists` and the dependency versions (Ceres, Eigen) that the 3.2 release and a 3.4 build pull.

Our tree is a shallow clone, and 3.2.x is not reachable from it. Use a full clone of
github.com/alicevision/AliceVision, or the GitHub compare view.
