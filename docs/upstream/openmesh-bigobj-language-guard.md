# Upstream draft: OpenMesh exports `/bigobj` without a language guard

**Target:** OpenMesh (gitlab.vci.rwth-aachen.de/OpenMesh/OpenMesh) - an issue rather than an MR,
since the exact source line has not been located in their tree from here.
**Status:** draft, not submitted

## Symptom

`OpenMeshConfig.cmake`, as generated by OpenMesh's own `install(EXPORT ...)`, contains:

```cmake
set_target_properties(OpenMeshCore PROPERTIES
  INTERFACE_COMPILE_FEATURES "cxx_std_11"
  INTERFACE_COMPILE_OPTIONS "/bigobj"
  INTERFACE_INCLUDE_DIRECTORIES "${_IMPORT_PREFIX}/include"
)
```

`/bigobj` is an MSVC C/C++ option, but the property carries no `COMPILE_LANGUAGE` guard, so it is
applied to **every** source in any target that links `OpenMeshCore` - including CUDA sources.

`nvcc` on Windows treats a leading `/` as a path, so the option arrives as a second input file:

```
nvcc fatal : A single input file is required for a non-link phase when an outputfile is specified
```

That message does not mention `/bigobj`, OpenMesh, or the option's origin, and the file compiles
perfectly well on its own - the flag comes from a link dependency two levels away.

## Suggested fix

Guard it the way pybind11 does in the same ecosystem
(`pybind11Common.cmake` sets `$<$<COMPILE_LANGUAGE:CXX>:/bigobj>`):

```cmake
target_compile_options(OpenMeshCore PUBLIC $<$<COMPILE_LANGUAGE:C,CXX>:/bigobj>)
```

`INTERFACE_COMPILE_OPTIONS` supports generator expressions, and the exported config preserves
them, so this costs nothing for C++ consumers and stops the option reaching other languages.

## Why nobody has hit it

It requires a CUDA (or HIP, or Fortran) source inside a target that links OpenMesh. That is an
unusual combination - a mesh library and a GPU kernel in one target - which is presumably why an
option that cannot work outside C/C++ has been exported unguarded for a long time without
complaint.

## Workaround, if useful to others

Restate the option, guarded, before creating the target:

```cmake
foreach(t OpenMeshCore OpenMeshTools)
    if (TARGET ${t})
        get_target_property(opts ${t} INTERFACE_COMPILE_OPTIONS)
        if (opts AND "/bigobj" IN_LIST opts)
            list(REMOVE_ITEM opts "/bigobj")
            list(APPEND opts "$<$<COMPILE_LANGUAGE:C,CXX>:/bigobj>")
            set_target_properties(${t} PROPERTIES INTERFACE_COMPILE_OPTIONS "${opts}")
        endif()
    endif()
endforeach()
```

## Note on vcpkg

The copy observed was installed by vcpkg, but the file is generated by OpenMesh's own export, so
the fix belongs upstream. vcpkg could carry a port patch in the meantime if upstream is slow.
